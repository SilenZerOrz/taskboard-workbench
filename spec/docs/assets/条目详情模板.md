# 条目详情模板（可直接复制）

> 配套文档：[`../02-流程执行与条目.md`](../02-流程执行与条目.md) §三（骨架与预算）。
> 用法：复制 A 或 B 的空骨架，把 `<>` 填掉。写完过一遍下面的「五问自检」。

---

## A. 任务卡（空骨架 · 七块全填）

```markdown
<编号>｜<动词开头的一句话：做完什么>

目标：<这张卡做完解决谁的什么问题；一句话，不写做法>
范围：<文件:行 / 条目编号 / 章节>；包含：<…>；移出：<…>
禁止：<项目硬禁令中与本卡相关的几条> + 本轮特禁：<…>
做法：
1. <先贴原文（文件:行）>
2. <改什么>
3. <再贴原文 + 跑哪条命令>
报告：四节证据（判定 / 偏离说明 / 边界自查 / 产物路径）+ <本类额外读数：如 dist-tags / 渲染后 DOM / 台架 n/n>
停下：报错 / 超范围 / 验收不满足 / 需要新变量 ⇒ 停，不重试；<本卡特有停机条件>
验收：
① <读数 1>
② <读数 2>
③ <读数 3>
关联：<需求 ref> · <依赖卡> · <文档 §> · <上游 PR>
```

## B. 需求条目（空骨架 · 五块必填）

```markdown
<编号>｜<一句话：这条需求要达成什么>

目标：<对外可感知的结果，不是实现手段>
范围：包含：<…>；移出：<**必填**，否则范围无边界>
约束：<硬禁令引用 + 口径约束：不改 schema / 不动生产进程 / 须人拍…>
验收：
① <能判真假的读数 1>
② <读数 2>
③ <读数 3>
关联：<设计稿 / 上游仓库 / 关联卡 / 其它需求>（没有就写「无」）
背景：<可选，≤5 行，只写「为什么现在做」>
```

## C. 填好的卡（示例）

```markdown
<你的项目>-999｜把「来源」列的 mcp 条目正确显示为 MCP

目标：MCP 建的需求条目在界面上不再被标成「手工」，人能一眼看出是谁建的。
范围：`web/app.js` 的两处来源三元链；包含：列表胶囊 + 详情字段；移出：数据层 source 值、其它来源档位。
禁止：不整文件重写；不动 `:3080`。
做法：
1. 先贴两处三元链原文
2. 各加一个 `mcp` 分支
3. 再贴原文 + 跑渲染验证台
报告：四节证据 + 验证台 n/n + 旧前端反证读数。
停下：反证不转红（说明守卫没守住）⇒ 停，先修守卫。
验收：
① 列表里 `source="mcp"` 显示「MCP」
② 详情「来源」字段＝「MCP」
③ `intake` 条目仍显示「资料索引（引入）」
关联：R-xxx · 文档 §三
```

## 五问自检（写完逐条过）

1. 第一行是不是「`<编号>｜一句话`」？
2. 「范围」有没有**同时**写「包含」与「移出」？
3. 验收的每一条，别人拿过去能不能**判真假**？
4. 有没有整段粘文档？有就改成指针。
5. 字符数在预算内吗（需求 ≤1200 / 卡 ≤800 / 验收 3–6 条）？
