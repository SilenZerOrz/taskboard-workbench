# 随包文档 · 开局与流程约束（人读版）

这个目录是**任务工作台随包分发的人读文档**：装完插件就能看到「项目怎么开局、流程怎么走、条目怎么写」，
不必依赖作者机器上的 `docs/`。

它是**通用版**：写给任何项目，不含作者本仓的历史读数与内部路径。

## 两份文档，各管一层

| 层 | 位置 | 管什么 |
|---|---|---|
| **人读版**（本目录） | `spec/docs/` | **为什么**这么定：开局清单、流程全环、反例与代价 |
| **机器版** | `spec/norms/` | **判据**：骨架、长度预算、门禁口径；写操作时按它校验契约 |

改人读文档**不影响**契约；只有改 `spec/norms/` 里的规范正文才会改契约版本（且必须 bump `version`）。

## 目录

- [`01-项目开局.md`](./01-项目开局.md) —— 新项目从零到「第一条闭环」的六步清单与自检表
- [`02-流程执行与条目.md`](./02-流程执行与条目.md) —— 需求 → 卡 → 认领 → 执行 → 证据 → done 全环；条目骨架与预算
- [`assets/条目详情模板.md`](./assets/条目详情模板.md) —— 可直接复制的卡 / 需求骨架

## 这些文档放在哪（三处）

1. **包内默认位置**：安装后随包就在（插件的 `spec/docs/`），**只读**，升级会被覆盖；
2. **项目存放位置**：默认 `<你的工作区>/.taskboard/docs/`，由配置页「生成默认副本」写入，**可改**；
3. **生效来源**：看板读文档时优先项目副本，缺的回落包内 —— 配置页会显示当前是哪一种。

## 想改成自己的规矩

1. 配置页 →「文档与规范位置」→ **生成默认副本**；
2. 直接编辑项目副本里的 `.md`；
3. 只在本机生效就不管它；想团队共享就把该目录 `git add` 进你的仓库（要不要入库由你定）。

> 若你要改的是**会被看板强制校验**的规则（骨架 / 预算 / 验收条数），那是 `spec/norms/` 的事 ——
> 项目副本里的规范正文改了**必须同时把 `version` 加 1**，否则会被判「规范被偷偷改了」并拦写。
