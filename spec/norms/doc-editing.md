# doc-editing · 文档更新规范（机器版）

## 每轮收尾（缺一即该轮未完成）

1. 更新 `docs/进度/当前状态.md`（唯一进度快照）。
2. 追加轮次记录 `docs/进度/YYYY-MM-DD-<主题>.md`：现象 / 根因 / 修复 / 验证 / 遗留。
3. 同步 `docs/README.md` 与相关 `README.md` 索引。
4. 回报里给出「文档更新清单」（改了哪几份 + 路径）。

## 写入纪律

- **先落文档，再动手**：口径/方案类先写进 `docs/设计/`，代码跟着文档走。
- **不改历史决策**：`docs/历史归档/`、已定稿条款不动；要改就加「变更记录」并写理由。
- **一条事实只写一处**：同一结论不重复散落；引用用相对链接。
- **敏感信息先脱敏**：`sk-*` / `*_token` / 密码 / 私钥 / 含凭据连接串 ⇒ 占位符（`sk-REDACTED`）。
- **读数必须可复跑**：写进文档的每个数字后面要有能重跑的命令。

## 命名

| 类型 | 规则 |
|---|---|
| 轮次记录 | `YYYY-MM-DD-<主题>.md`（同日同主题追加，不新建） |
| 设计方案 | `<主题>-方案-YYYY-MM-DD.md` |
| 踩坑 / 复盘 | 归 `个人笔记/踩坑经验/<主题>/`，**不写进本仓 `docs/`** |
