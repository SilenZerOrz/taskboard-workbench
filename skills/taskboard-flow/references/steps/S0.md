# S0 · 绑定与对照

## 目标
在**动手之前**确认三件事：这是哪个项目、用的是哪版契约、现在缺什么。

## 命令
```bash
node scripts/tb-flow.mjs start            # 人贴进会话的装载块（档 A）
node scripts/tb-flow.mjs start --json     # 机器读
```
MCP：`flow_start { project?, cwd? }` · `project_info { project }` · `workbench_audit { project }`

> 三个都是只读。`project_info` 看全貌计数，`workbench_audit` 看四类漂移（`contract-stale` /
> `unattributed` / `unbound-session` / `candidate-flood`）。

## 判据（读数长什么样）
- `project.id` 与你要动的项目一致（不一致 ⇒ 显式带 `project`）；
- `contract.version` 形如 `v1-xxxxxxxxxxxx`，且 `contract.baselineStale === false`（`true` ⇒ 规范或需求文档刚变过，先读 `changed[]`）；
- `gaps` 三个数看清楚：`unattributedTasks` / `unboundSession` / `pendingCandidates`；
- `nextStep.step` 给出 S1–S7 里的一个 —— **这就是本轮该先做的事**。

## 失败处置
| 现象 | 处置 |
| --- | --- |
| `PROJECT_NOT_FOUND` | 项目还没建，或 `cwd` 不在任何项目工作区 ⇒ 显式传 `project` |
| `gaps.unboundSession === true` | 项目主会话没绑定 ⇒ 回看板「重建/绑定主会话」，否则投递会落空 |
| `pendingCandidates > 20` | 先确认/丢弃候选（`candidate-flood`），否则条目化会灌进一堆文件清单行 |

## 别做的事
- 这一步**只读**：不要在这里建卡、改状态、写评论。
- 不要凭记忆说"规范我知道" —— `norm_get` 一屏就能读完，`digest` 还是后续写操作的通行证。
