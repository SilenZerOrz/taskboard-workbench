# S3 · 授权开工（人）

## 目标
把卡从待办池放行。**这一步只有人能做**。

## 谁来做
看板上的「启动执行」/ 拖拽 / 人点 —— 不是 agent，也不是 MCP 工具。

## 判据
- 卡 `status` 从 `backlog` 变 `todo`；
- `task_events` 里有 `set-status`，`actor=human`；
- 卡此时已有归因（`requirement_id` 非空），否则下一步派发会被 `EXECUTION_NOT_ATTRIBUTED` 拒。

## 失败处置
| 现象 | 处置 |
| --- | --- |
| 执行侧尝试推进 ⇒ `AUTHORIZATION_REQUIRED` | 这是设计：执行侧不得自我授权。请人点 |
| 卡还没归因就想授权 | 先回 S2 补归因，再请人授权 |

## 别做的事
- 不要用 `card_progress` 试图把卡推到 `todo` —— 它走执行侧状态门，只接受 `in_progress` / `in_review` / `blocked` / `canceled`。
- 不要"先授权再想清楚要做什么"：授权意味着占用执行资源。
