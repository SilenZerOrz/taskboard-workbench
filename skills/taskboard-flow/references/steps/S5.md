# S5 · 回填进度 + 证据

## 目标
把"做到哪了"写成**别人能复核**的证据，而不是一句"已完成"。

## 命令
```
card_progress {
  card,
  status: "in_progress" | "in_review" | "blocked" | "canceled",   # 可选
  evidence: [
    { kind: "command", ref: "npm test", note: "900/900 pass" },
    { kind: "file",    ref: "src/mcp/tools.mjs:210", note: "注册表新增 5 个工具" },
    { kind: "reading", ref: "gaps.unattributedTasks=0" }
  ],
  norm_digest: "<norm_get {norm:'card-update'} 返回的 digest>"
}
```

## 判据
- `evidence[].kind` ∈ `file` / `command` / `url` / `reading`，`ref` 非空；
- 返回 `comment.deduped === false`（第二次同样证据会是 `true`，不会刷重复评论）；
- `card.statusAfter` 与你期望的一致；
- 评论正文里有 `【MCP 证据】hash=…` —— 这就是事后复核的锚点。

## 失败处置
| 错误码 | 该怎么办 |
| --- | --- |
| `EVIDENCE_REQUIRED` / `EVIDENCE_INVALID` | 补形状，不要改成"详见上文" |
| `NORM_DIGEST_REQUIRED` | 先 `norm_get { norm: "card-update" }`，用返回的 `digest` |
| `NORM_STALE` | 规范换版了 ⇒ 读返回体里的 `body` 再回填（**它已经把最新正文给你了**） |
| `GOVERNANCE_AGENT_DONE` | 想写 `done` ⇒ 不行，完成只能人点（回 S7 交人） |

## 别做的事
- 不要把 `npm test` 的"退出码 0"写成"全部通过"：说清楚跑了多少条。
- 不要用同一条证据反复回填不同卡 —— 去重是按**卡 + 这批证据**算的，换卡就算新证据。
