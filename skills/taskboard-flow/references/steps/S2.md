# S2 · 分拆成卡

## 目标
把条目拆成**可执行、可验收、可归因**的卡。

## 命令
```
card_create {
  project, title, requirement,          # requirement 必填（或 unattributed_reason）
  acceptance, verifyCommand,            # FR-94：建卡时就写验收标准与复核动作
  dependsOn: ["-12"]                    # 可选：前置卡，建卡后真成依赖边
}
```

## 判据
- `attribution.kind === "requirement"`（不是 `explicit-skip`）；
- `card.status === "backlog"`（新卡只能待办池）；
- `dependsOn` 回显的边数与你要的一致；
- `duplicates` 非空 ⇒ 已有同名未终态卡，**先确认是不是重复**再继续。

## 失败处置
| 错误码 | 该怎么办 |
| --- | --- |
| `REQUIREMENT_REQUIRED` | 没给 `requirement` 也没给 `unattributed_reason` ⇒ 补一个；真不需要归属就显式写理由（落审计，可盘点） |
| `AUTHORIZATION_REQUIRED` | 想直接建进 `todo` ⇒ 不行：`backlog → todo` 是人工授权 |
| `DEPENDENCY_CROSS_PROJECT` / `TASK_NOT_FOUND` | 前置卡挂错项目或编号写错 —— **这次建卡没有发生**（依赖先解析，不会留半张卡） |
| `USAGE_ERROR`（两个都给） | `requirement` 与 `unattributed_reason` 只能二选一 |

## 别做的事
- 不要一次建十张卡再回头补验收标准 —— `acceptance` / `verifyCommand` 建卡时就要写。
- 不要用 `unattributed_reason` 当"懒得找条目"的捷径：它会被 `workbench_audit` 盘点出来。
