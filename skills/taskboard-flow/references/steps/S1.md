# S1 · 需求文档与条目

## 目标
把「要做什么」写成**一条一件事**的需求条目；确认过再往下走。

## 命令
MCP：
```
requirement_list   { project }
requirement_upsert { project, title, description, acceptance }        # 新建
requirement_upsert { project, id, expected_version, title }          # 改（必须带 version）
```

## 判据
- 一条条目只讲一件事（"顺便把 X 也做了"要拆成两条）；
- `status` 不是 `draft` 才算确认过（`draft` 不得建卡）；
- 改条目返回的 `item.version` 与上次不同 ⇒ 确实改成了。

## 失败处置
| 错误码 | 该怎么办 |
| --- | --- |
| `MISSING_VERSION` | 改条目没带 `expected_version` ⇒ 先 `requirement_list` 取 `version` 再提交 |
| `VERSION_CONFLICT` | 别人改过了 ⇒ 重新取 `version`，**在你的改动上合并**，别把人家的改动覆盖掉 |
| `DEPENDENCY_CROSS_PROJECT` | 条目属于别的项目 ⇒ 回到正确项目 |

## 别做的事
- 不要用 `requirement_upsert` 改需求**正文**——正文属需求文档，条目是它的投影。
- 不要靠"条目名字看起来对"挑条目：`requirement_list` 会给你 `tasks.total`，没卡的条目才是待拆的。
