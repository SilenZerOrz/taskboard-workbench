# S4 · 派发 / 执行

## 目标
让卡真正跑起来，并且跑的过程可追踪。

## 命令 / 入口
- 看板「派发团队」/「交项目主会话执行」（需要宿主会话通道；独立进程实例会如实置灰并给替代出口）；
- 执行侧推进状态用 MCP `card_progress { card, status: "in_progress", evidence, norm_digest }`。

## 判据
- 卡 `in_progress` 且有认领心跳（离开 `in_progress` 会自动释放认领）；
- 人工校验任务（`labels` 含人工校验）**不会被执行侧改状态**；
- 每次状态变化都有 `task_events` 留痕。

## 失败处置
| 错误码 | 该怎么办 |
| --- | --- |
| `HUMAN_REVIEW_NOT_EXECUTABLE` | 这是人在环任务 ⇒ 交人做结论（continue / change-requirement / close），执行侧别碰 |
| `EXECUTION_NOT_ATTRIBUTED` | 卡没有归属条目 ⇒ 回 S2 |
| `host-unavailable` | 当前是**独立进程**实例（没有宿主会话通道）⇒ 换到 DSH 内的 `/integrations/taskboard-workbench`，或按返回的 `prompt` 手工投递 |
| 卡长时间 `in_progress` 无心跳 | 看护会判 `stalled`；先看它的最后一条证据评论，别急着重派 |

## 别做的事
- 不要为了"看起来在跑"而重复派发 —— 同一张卡重复派发会抢锁。
- 不要在派发前跳过 `dependsOn`：受阻卡派发了也只会被依赖门挡住。
